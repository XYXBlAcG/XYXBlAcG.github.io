# Easy Math Solver 高效输入系统设计

## 背景

当前 `work/py_software/function_solver.html` 里的输入方式按功能拆成多个独立表单：单方程、多方程、矩阵、积分、求和、化简等各自维护输入框和按钮。这个结构存在三个核心问题：

1. 高频用户需要频繁切换模式和输入框，键盘效率低。
2. 矩阵、方程组、上下界这类结构化数据依赖手写分隔符，容易输错。
3. Python 端的计算入口分散在多个 `runsrc_*` 函数中，解析、计算和输出耦合在一起，后续功能会继续变乱。

本设计目标是建立一个“智能文本输入 + 可视化编辑器”的混合输入系统，在保留旧功能可用的前提下，提高公式、矩阵、方程组等输入效率。

## 目标

- 提供一个主智能输入框，支持键盘快速输入常见数学任务。
- 提供可视化输入方式，用于矩阵、方程组、积分/求和上下界等结构化输入。
- 增加解析预览，让用户在计算前看到系统理解出的任务类型、变量和表达式。
- 统一 Python 计算入口，减少 `runsrc_*` 的重复 DOM 读取和重复输出逻辑。
- 统一输出格式，包含普通结果、Latex 结果、可复制结果和错误提示。
- 保留旧模式作为迁移期 fallback，避免一次性破坏已有功能。

## 非目标

- 不在第一阶段实现完整 CAS 语法编辑器。
- 不引入大型前端框架。
- 不重写 SymPy 计算核心。
- 不把所有输入都强制变成可视化表单；高级用户仍应能用键盘完成绝大多数任务。

## 用户体验设计

### 主输入区

页面新增一个“智能输入”模式，作为默认推荐入口。

结构：

```text
智能输入
┌──────────────────────────────────────────────┐
│ solve x: x + 1 = 0                            │
└──────────────────────────────────────────────┘

[计算] [解析预览] [插入模板] [可视化输入] [清空]

解析预览
类型：解方程
变量：x
方程：x + 1 = 0
```

用户可以直接输入命令，也可以通过模板和可视化编辑器生成命令。

### 智能输入语法

第一版只支持小而稳定的语法，避免做过度复杂的语言。

#### 解单变量方程

```text
solve x: x + 1 = 0
```

解析结果：

```json
{
  "type": "solve",
  "variables": ["x"],
  "equations": ["x + 1 = 0"]
}
```

#### 解方程组

```text
solve x y:
  x + y = 3
  x - y = 1
```

也支持紧凑写法：

```text
solve x y: x + y = 3; x - y = 1
```

#### 求导

```text
diff x: x**3 + sin(x)
```

#### 积分

不定积分：

```text
integrate x: x**2
```

定积分：

```text
integrate x from 0 to 1: x**2
```

#### 求和

```text
sum n from 1 to 10: n**2
```

#### 化简、展开、因式分解

```text
simplify: (x + 1)**2 - x**2
expand: (x + 1)**3
factor: x**2 - 1
trigsimp: sin(x)**2 + cos(x)**2
```

#### 矩阵

```text
matrix A = [[1, 2], [3, 4]]
matrix B = [[0, 1], [1, 0]]
calc A * B
```

或者一次输入：

```text
matrix A = [[1,2],[3,4]]; calc A**2
```

## 可视化输入设计

可视化输入不是另一套计算系统，而是“结构化命令生成器”。它生成智能输入框里的文本，然后复用同一套解析和计算逻辑。

### 可视化输入入口

点击“可视化输入”按钮后打开一个轻量面板，顶部使用 tabs：

```text
[方程组] [矩阵] [积分] [求和] [表达式]
```

每个 tab 都提供结构化输入，并有两个动作：

- `插入到智能输入`：生成命令文本但不计算。
- `插入并计算`：生成命令文本后直接计算。

### 方程组编辑器

字段：

- 变量列表：可输入 `x y z`，也可点击“自动识别变量”。
- 方程列表：一行一个方程。
- 添加/删除方程按钮。

生成示例：

```text
solve x y:
  x + y = 3
  x - y = 1
```

### 矩阵编辑器

字段：

- 矩阵名：默认 `A`，可改。
- 行数、列数：用步进器调整。
- 表格单元格：每格一个数或表达式。
- 矩阵表达式：例如 `A**2`、`A.inv()`、`A * B`。

生成示例：

```text
matrix A = [[1, 2], [3, 4]]
calc A**2
```

扩展支持：

- 可添加多个矩阵。
- 可从粘贴文本解析矩阵，例如 `1 2; 3 4`。
- 可导入旧格式 `1,2;3,4#2,3;4,5` 并转换为新格式。

### 积分编辑器

字段：

- 变量：如 `x`。
- 被积函数。
- 积分类型：不定积分 / 定积分。
- 下界、上界：仅定积分显示。

生成示例：

```text
integrate x from 0 to 1: x**2
```

### 求和编辑器

字段：

- 求和变量。
- 下界、上界。
- 表达式。

生成示例：

```text
sum n from 1 to 10: n**2
```

### 表达式编辑器

提供常用操作按钮：

- `化简`
- `展开`
- `因式分解`
- `三角化简`

用户输入表达式后选择操作，生成：

```text
factor: x**2 - 1
```

## 解析与计算架构

### 前端职责

前端负责：

- 管理智能输入框内容。
- 打开/关闭可视化输入面板。
- 从可视化编辑器生成命令文本。
- 显示解析预览和结果。
- 调用 Python 统一入口。

前端不直接实现数学计算。

### Python 职责

Python 端新增统一入口：

```python
def run_solver(raw_input: str, mode: str | None = None) -> dict:
    task = parse_input(raw_input, mode)
    result = dispatch_task(task)
    return format_result(result)
```

### 任务对象

解析器输出统一任务对象：

```python
{
    "type": "solve",
    "variables": ["x"],
    "equations": ["x + 1 = 0"]
}
```

矩阵任务：

```python
{
    "type": "matrix",
    "matrices": {
        "A": [[1, 2], [3, 4]]
    },
    "expression": "A**2"
}
```

积分任务：

```python
{
    "type": "integrate",
    "variable": "x",
    "expression": "x**2",
    "bounds": ["0", "1"]
}
```

### 分层函数

建议拆成以下职责：

- `parse_input(raw_input, mode)`：把文本解析为任务对象。
- `parse_matrix_literal(text)`：解析矩阵字面量。
- `dispatch_task(task)`：按 `type` 分派计算。
- `solve_task(task)`：解方程/方程组。
- `matrix_task(task)`：矩阵计算。
- `calculus_task(task)`：求导、积分、求和。
- `expression_task(task)`：化简、展开、因式分解。
- `format_result(value)`：统一生成 plain、latex、copyable。
- `render_result(result)`：写入 DOM 输出区。

## 输出设计

统一输出结构：

```json
{
  "ok": true,
  "kind": "solve",
  "plain": "[-1]",
  "latex": "$$-1$$",
  "copyable": "[-1]",
  "warnings": []
}
```

错误输出：

```json
{
  "ok": false,
  "kind": "parse_error",
  "plain": "无法识别输入：solve x x + 1 = 0。是否缺少冒号？",
  "latex": "",
  "copyable": "",
  "warnings": []
}
```

输出区显示：

- 结果文本。
- Latex 渲染。
- 可复制文本。
- 错误提示和修复建议。

## 兼容策略

第一阶段保留旧输入模式和旧按钮，不立刻删除现有 `runsrc_*`。

迁移顺序：

1. 新增智能输入模式。
2. 新增解析器和统一输出函数。
3. 将单方程、方程组、求导、积分、求和、化简接入统一入口。
4. 新增矩阵可视化编辑器，并兼容旧矩阵格式。
5. 将旧模式按钮内部改为调用统一入口。
6. 稳定后再决定是否隐藏旧模式。

## 测试样例

### 解析测试

```text
solve x: x + 1 = 0
```

期望任务：

```json
{"type":"solve","variables":["x"],"equations":["x + 1 = 0"]}
```

```text

```


### 计算测试

- `solve x: x + 1 = 0` 输出 `[-1]`。
- `diff x: x**3` 输出 `3*x**2`。
- `integrate x from 0 to 1: x**2` 输出 `1/3`。
- `sum n from 1 to 10: n` 输出 `55`。
- `factor: x**2 - 1` 输出 `(x - 1)*(x + 1)`。
- `matrix A = [[1,2],[3,4]]; calc A.det()` 输出 `-2`。

### UI 测试

- 打开页面后智能输入模式可见。
- 点击“插入模板”能填入示例命令。
- 可视化矩阵编辑器能生成 `matrix A = ...`。
- 修改矩阵行列不会造成布局溢出。
- 移动端 390px 宽度下无横向滚动。
- 输入错误时显示具体错误，而不是静默失败。

## 风险

- DSL 语法如果一次设计过大，会变成新的维护负担。第一版必须保持小而明确。
- 旧代码大量使用 `eval` 和分散的 DOM 读写，迁移时需要小步推进。
- PyScript 加载慢，智能输入 UI 应先可见，计算按钮可以显示“计算环境加载中”。
- 矩阵编辑器不能只做漂亮表格，必须支持粘贴和快速键盘输入，否则效率不够。

## 推荐实施路线

推荐采用渐进式迁移：

1. 新增智能输入区和解析预览，不删除旧功能。
2. 新增 Python 解析器和统一输出结构。
3. 先接入单方程、求导、化简这类简单任务。
4. 再接入积分、求和、方程组。
5. 最后做矩阵编辑器和矩阵任务迁移。

这样每一步都有可验证的功能，不会一次性重写整个项目。
